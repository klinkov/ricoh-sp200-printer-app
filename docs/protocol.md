# SP 202SN — факты с железа

## Сеть (2026-10-21, принтер 192.168.1.60)

- SNMP v1 `public` работает. `sysDescr` = `RICOH SP 202SN DDST V1.02 / RICOH Network Printer C model / RICOH Network Scanner C model / RICOH Network Facsimile C model`.
- Порты: 80 (веб-панель `Web-Server/3.0`), 515 (LPD), 631 (слушает, но IPP `Get-Printer-Attributes` → `server-error-operation-not-supported`, использовать нельзя), 9100 (raw). Закрыты: 443, 8080, 8000, 9101, 9220, 54921 и др.
- Bonjour: принтер ничего не анонсирует (`_printer`, `_pdl-datastream`, `_ipp`, `_uscan`, `_scanner` — пусто). eSCL (`/eSCL/ScannerCapabilities`) — пустой ответ. Сканер: протокол проприетарный, см. этап 4.
- Транспорт для драйвера: `socket://192.168.1.60:9100` (основной), LPD 515 — запасной.

## Веб-панель (Web Image Monitor, http://192.168.1.60/)
- `H02_Home_status.htm`: «Общий счётчик» = 9172 (отличается от SNMP prtMarkerLifeCount 9219 — разные счётчики; для этапа 0a фиксировать оба), тонер — только графическая шкала 0/50/100.
- `H11_device_info.htm`: серийник, память 32 MB. Точного счётчика тонера нет → DOTCOUNT проверять через SNMP `prtMarkerSuppliesLevel` на большом объёме печати либо принять /100 (вариант фильтра, заявившего SP 202SN) и наблюдать.

## Device-ID по SNMP (для auto-add)
- PWG OID `1.3.6.1.4.1.2699.1.2.1.2.1.1.3.1` → `MFG:RICOH ;CMD:GDI;MDL:SP 202SN DDST;CLS:PRINTER;` (обратить внимание: пробел после RICOH, суффикс ` DDST` в модели).
- HP/Lexmark OID не отвечают. `hrDeviceDescr.1` = `RICOH SP 202SN DDST`.

## Сквозная печать с macOS (2026-10-21)
- Очередь CUPS: `lpadmin -p SP202SN -E -v ipp://localhost:8000/ipp/print/sp202sn -m everywhere`; `lp -d SP202SN hello.pdf` → macOS шлёт `image/urf` с `compression=gzip`; принтер напечатал (счётчик 9224 → 9225).
- **macOS Local Network (TCC):** свежесобранный ad-hoc-подписанный бинарник, запущенный из сессии Claude, получает `No route to host` (EHOSTUNREACH) при TCP-connect к принтеру, тогда как системные `nc`/`python3` подключаются. Включение Claude в Privacy → Local Network без перезапуска не помогло. Запуск сервера из Terminal.app с разрешением локальной сети — работает. Для `brew services` ожидать системный запрос «…хочет найти устройства в локальной сети» от имени бинарника; описать в README.
- Если очередь CUPS уходила в `printer-stopped` (устройство было недоступно), нужно `cancel` старого задания и `cupsenable SP202SN`.

## Новая сборка (ricoh-socket://), 2026-10-21
- Два задания подряд из очереди CUPS (`hello.pdf`, `job2.pdf`): оба completed, 2 листа, счётчик 9225 → 9227, ~40 с от `lp` до idle.
- Half-close (`shutdown(SHUT_WR)`) в конце задания: принтер закрывает соединение сразу (задания 1 и 2 завершились с разницей 0,2 с), ожидания 10 с нет. Одно TCP-соединение на задание — рабочая схема.
