# RICOH SP 202SN — драйвер печати для macOS 26+ (дизайн)

Дата: 2026-10-21. Статус: черновик на согласование.

## 1. Зачем

RICOH SP 202SN — host-based (GDI) лазерное МФУ: принтер не понимает PostScript/PCL, ему нужен готовый растр
в фирменном потоке «DDST» (PJL + JBIG1). Официального драйвера для современных macOS нет. Apple объявила
PPD/CUPS-фильтры устаревшими (apple/cups#5270); на macOS 26 они ещё исполняются, но дата удаления не названа.

Цель: печатать на SP 202SN с macOS 26 и новее по сети (Ethernet/Wi-Fi), без зависимости от PPD-механизма.
Вторая очередь: сканирование по сети.

## 2. Решение (принято пользователем)

- **Архитектура:** Printer Application на [PAPPL](https://github.com/michaelrsweet/pappl). Локальный сервис
  поднимает IPP Everywhere-принтер, анонсирует его через Bonjour; macOS видит «сетевой AirPrint-принтер» и шлёт
  растр (PWG/URF). Сервис конвертирует растр в DDST и передаёт на физический принтер.
- **Подключение:** принтер в локальной сети. Транспорт — PAPPL device URI `socket://<ip>:<port>` (ожидается
  raw 9100; подтвердить на железе — см. §7, этап 0).
- **Объём:** печать (первая очередь) + сканер (вторая очередь, отдельный этап со своим go/no-go).
- **Доставка:** Homebrew tap + `brew services` (launchd-агент при входе). Без .pkg и нотаризации.
- **Площадка:** `/Users/shade/Work/Personal/ricoh` (git-репозиторий, создать).

## 3. Цели / не-цели / анти-цели

Цели
- Печать из любого приложения macOS 26+ через стандартный диалог: A4/Letter/A5/B5/Legal/Executive, 600 dpi,
  лоток 1 и ручная подача, число копий, порядок страниц.
- Печать без железа тестируется автоматически (mock-приёмник потока).
- Семейство SP 200 (200/201/202/203/204 и их S/SN/SF-варианты) — тот же протокол; поддерживать «best effort»,
  тестируется только SP 202SN.
- Установка одной командой `brew install klinkov/ricoh/ricoh-sp200-printer-app && brew services start …`.

Не-цели
- Поддержка SP 100/110/150 серий (другие размеры/настройки; код не должен мешать добавить, но не делаем).
- 1200×600 dpi (Ricoh заявляет для SP 200; поток для него не задокументирован). Сначала 600×600.
- Авто-дуплекс (аппаратно отсутствует, только ручной).
- Windows/Linux-сборки.
- Копирование, факс.

Анти-цели (провал даже при «работает»)
- Зависимость от Ghostscript/ImageMagick/netpbm в рантайме. Конвертация — только своя C-библиотека + libjbig.
- Решение, которое перестанет работать при удалении PPD из macOS.
- Печать, портящая счётчики тонера (неверный DOTCOUNT) или оставляющая принтер в «зависшем» состоянии.

## 4. Протокол (из Linux-драйверов; требует подтверждения на железе)

Источники: `revisitor/ricoh-sp100` (shell-фильтр, SP 202SN заявлен), `ankitsingh99/ricoh-universal-ddst-driver`
(C-фильтр, MIT, проверен только на SP 200). Подробнее: `docs/research-2026-10-21.md`.

Поток на задание (строки с CRLF, `<ESC>` = 0x1B):

```
<ESC>%-12345X@PJL
@PJL SET TIMESTAMP=YYYY/MM/DD HH:MM:SS
@PJL SET FILENAME=<имя>
@PJL SET COMPRESS=JBIG
@PJL SET USERNAME=<пользователь>
@PJL SET COVER=OFF
@PJL SET HOLD=OFF
-- на каждую страницу --
@PJL SET PAGESTATUS=START
@PJL SET COPIES=<n>
@PJL SET MEDIASOURCE=TRAY1|MANUAL
@PJL SET MEDIATYPE=PLAINRECYCLE
@PJL SET PAPER=A4|LETTER|…
@PJL SET PAPERWIDTH=<px>
@PJL SET PAPERLENGTH=<px>
@PJL SET RESOLUTION=600
@PJL SET IMAGELEN=<байт JBIG>
<JBIG-данные>
@PJL SET DOTCOUNT=<число>
@PJL SET PAGESTATUS=END
-- конец задания --
@PJL EOJ
<ESC>%-12345X
```

JBIG1 (ITU-T T.82) через libjbig (jbigkit): 1 плоскость, options = LRLTWO|TPBON (0x48), order = ILEAVE|SMID
(0x03), 128 строк в полосе; эквивалент `pbmtojbg -p 72 -o 3 -m 0`.

Неоднозначности, снимаются на этапе 0:
- DOTCOUNT: shell-фильтр шлёт `чёрные_пиксели/100`, C-фильтр — чистый popcount. Проверить, что принтер
  принимает и как меняется счётчик в веб-панели/отчёте.
- PAPERWIDTH/PAPERLENGTH для A4@600: ожидаемо 4960×7016; в C-драйвере пример 4760×6736 (возможно, с полями).
  Снять точные значения с захвата трафика родного Windows-драйвера или подобрать печатью тестовой сетки.
- Порт/протокол сетевой печати (9100 raw? LPD 515? IPP?). Принтер на момент разведки в сети не найден.
- Нужны ли `PAGESTATUS=START` на каждую страницу или только в преамбуле.

## 5. Устройство

```
macOS print dialog ──IPP/URF──▶ ricoh-sp200-printer-app (PAPPL, launchd via brew services, localhost:8000)
                                   │  driver callbacks: rstartjob/rstartpage/rwriteline/rendpage/rendjob
                                   ▼
                               libddst (C, static): растр → 1-bit (дизеринг) → JBIG (libjbig) → PJL-кадры
                                   ▼
                               PAPPL device: socket://<ip>:9100  ──▶  SP 202SN
```

Компоненты (папки репозитория):
- `src/ddst/` — `libddst`: чистая C-библиотека без PAPPL-зависимостей. API: начать задание, начать страницу
  (ширина/высота/бумага/лоток/копии), подать строку 1-bit, закончить страницу (возвращает кадр с IMAGELEN и
  DOTCOUNT), закончить задание. Пишет в callback «отправить байты». Дизеринг 8-bit gray → 1-bit (упорядоченный
  или Флойд–Стейнберг; выбор строителя, но с переключателем по умолчанию «текст чёткий»).
- `src/app/` — Printer Application на PAPPL: описание драйвера (`pappl_pr_driver_data_t`: bitmap-разрешение
  600×600, media, источники, raster types), callbacks, сопоставление имён бумаги PWG → PJL `PAPER=`,
  авто-обнаружение (PAPPL dnssd/snmp-сканирование) + ручной ввод IP.
- `tools/` — `ddst-probe` (найти принтер, проверить порты 9100/515/631/80, SNMP sysDescr, эндпоинт eSCL),
  `ddst-send` (отправить готовый .ddst-файл на принтер), `pbm2ddst` (PBM → DDST, для этапа 0 и golden-тестов).
- `tests/` — юнит-тесты libddst (C, без фреймворка или с `greatest.h`), golden-файлы, интеграционный тест:
  поднять printer-app с mock-приёмником (`socket://127.0.0.1:9101` → файл), напечатать через `ipptool`/`lp`,
  сравнить поток.
- `Formula/` — Homebrew tap: `pappl.rb` (взять за основу `shawnz/homebrew-printing`, с macOS-патчами),
  `ricoh-sp200-printer-app.rb` с `service do … end`.
- `docs/` — исследование, спека, план, руководство пользователя.

Сборка: `make` (POSIX Makefile, clang; cmake в системе нет). Зависимости: `pappl` (из своего tap), `jbigkit`,
`libusb` (только как зависимость PAPPL), системный CUPS (`cups-config` 2.3.4 есть).

## 6. Качество и проверка

- Golden-тест кодека: тот же PBM через `pbmtojbg -p 72 -o 3 -m 0` и через libddst должны дать байт-в-байт
  одинаковый JBIG. `pbmtojbg` ставится из `jbigkit` только для тестов.
- Юнит-тесты: PJL-кадр для A4/Letter, DOTCOUNT на известных картинках, обработка нечётной ширины/паддинга строк.
- Интеграционный тест без железа: mock-приёмник, печать 3-страничного PDF, проверка количества страниц, IMAGELEN
  совпадает с длиной данных, EOJ в конце.
- Ручной тест на железе (чек-лист в `docs/hardware-test.md`): тестовая сетка с линейкой (проверка полей и
  масштаба), текст 6 pt, фото (дизеринг), 2 копии, ручная подача, отмена задания посреди печати, повторная
  печать после отмены.
- Бюджеты: холодный старт сервиса < 2 с; A4 текстовая страница — конвертация < 1 с на Apple Silicon; память
  процесса < 100 МБ при печати 50 страниц.

## 7. Этапы

0a. **Спайк протокола (выбрасываемый).** Скрипт `tools/pbm2ddst` + `ddst-send` → напечатать одну страницу на
   реальном принтере, снять ответы на неясности §4. Нужен включённый принтер. Критерий «готово»:
   - тестовая сетка напечатана, масштаб 100 % ± 0,5 мм по линейке, поля измерены и записаны;
   - счётчик страниц в веб-панели/отчёте принтера вырос ровно на 1;
   - DOTCOUNT: напечатать две страницы с известной чернотой (1 % и 50 %) в обоих вариантах (popcount и /100);
     принимается вариант, при котором счётчик тонера меняется пропорционально; если оба проходят — popcount/100
     как у фильтра, заявившего SP 202SN;
   - отмена: обрыв сокета посреди страницы и досылка `@PJL EOJ` + UEL — принтер возвращается в Ready без
     перезагрузки; результат фиксирует политику отмены (§10);
   - транспорт: порядок проб 9100 raw → LPD 515 → IPP 631; первый рабочий записывается в `docs/protocol.md`.
0b. **Проверка сборки PAPPL на macOS 26** (параллельно 0a, без железа): собрать `pappl` по формуле из
   `shawnz/homebrew-printing`, запустить `testpappl`, увидеть тестовый принтер в «Принтеры и сканеры». Если
   патчи не ложатся — чинить здесь, до этапа 2.
1. **libddst + тесты** (без железа).
2. **PAPPL printer-app** (без железа, mock-приёмник) → затем проверка на принтере по чек-листу.
3. **Homebrew tap + brew services + README.** Проверка чистой установки на этом Mac.
4. **Сканер — разведка (go/no-go).** Проверить eSCL (`/eSCL/ScannerCapabilities`), Bonjour `_uscan`, порты;
   если eSCL есть — macOS подхватит сам, нужна лишь документация; если нет — захват трафика родного драйвера
   и отдельный дизайн-документ. Текущих данных о протоколе сканера нет; PAPPL-сканирование в upstream не
   влито.

## 8. Оставлено строителю

- Алгоритм дизеринга и настройка порога по умолчанию.
- Внутренний буфер страницы (целиком в памяти: A4@600 1-bit ≈ 4,3 МБ, допустимо) vs потоковая подача полос.
- Способ передачи «ширина/длина в пикселях» (из PWG-заголовка vs таблица по имени бумаги) — после этапа 0.
- Имя сервиса/бинаря (`ricoh-sp200-printer-app`), порт веб-панели PAPPL.
- Структура Makefile и тестовый фреймворк.

## 10. Решения после проверки строителем (мои, не пользователя)

- **Транспорт, если raw 9100 нет.** PAPPL встроенных LPD-устройств не имеет; тогда добавляется своя схема
  `lpd://` через `papplDeviceAddScheme` (RFC 1179, ~200 строк C). USB через встроенную схему `usb://` PAPPL
  допускается как бесплатный фолбэк, но не тестируется и не обещается; `libusb` остаётся только как зависимость
  PAPPL.
- **Отмена и ошибки.** Принтер по raw-сокету статуса не отдаёт; состояние (нет бумаги, замятие) читается по
  SNMP (`hrPrinterStatus`, `prtAlertTable`) встроенными средствами PAPPL, если принтер отвечает на SNMP —
  проверяется на 0a. При отмене: прекратить подачу JBIG, дослать `@PJL SET PAGESTATUS=END`, `@PJL EOJ`, UEL,
  закрыть сокет. Если 0a покажет, что принтер после этого висит — политика меняется на «закрыть сокет и
  подождать N с», записать в `docs/protocol.md`.
- **Копии.** Делает принтер (`@PJL SET COPIES=n` на страницу). Collate тогда невозможен аппаратно; если
  клиент просит `multiple-document-handling=separate-documents-collated-copies`, сервис сам повторяет задание
  n раз с `COPIES=1`.
- **Сеть и доступ.** PAPPL слушает `0.0.0.0` (иначе Bonjour-анонс бесполезен), но доступ ограничивается
  `localhost` через `papplSystemSetHostName`/ACL; веб-панель без аутентификации (только localhost). Расшарить
  на другие Mac — не цель.
- **Лицензия.** Репозиторий MIT. `libddst` пишется заново по описанию протокола; читать MIT/Unlicense-код можно,
  копировать — нет (их качество неизвестно, у C-фильтра только SP 200 проверен).
- **Чистая установка (этап 3).** Критерий: `brew uninstall` обоих пакетов + `brew untap`, затем установка из
  GitHub-tap с нуля на этом же Mac, сервис стартует через `brew services`, принтер виден в «Принтеры и сканеры».
  Отдельный пользователь/VM не нужны.
- **Принтер.** Пользователь подтвердил, что принтер есть и подключён по сети; на 2026-10-21 он выключен/не в
  сети. Этапы 1 и 0b начинаются без него; 0a и аппаратная проверка этапа 2 ждут включения.
